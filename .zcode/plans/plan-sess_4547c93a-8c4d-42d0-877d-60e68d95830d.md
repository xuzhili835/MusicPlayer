# Sakura Echo 2.0 全面优化方案

**定位重塑**：从「B站音乐下载器」→「个人听力 / 播客 / 音乐中心」（樱花 Echo，学习陪伴向）。
**技术路线**：原生 JS 渐进重构（不引框架），保留 yt-dlp/ffmpeg/音量同步等全部现有资产。
**阶段顺序**：修 Bug 打底 → 隐私+老板键（最重要）→ UI 重设计+模块化 → 播放/听力特性 → YouTube → OCR → 收尾。

## Phase 2：隐私模式 + 老板键（最重要）

**渲染端**（新文件 `privacy.js`，经典脚本与现有结构一致，Phase 3 再归入模块化）：
- `enter()`：立即 `audio.pause()` → 全屏**不透明**遮罩（只显示低对比度 logo 的深色画面，**无任何文字提示**）→ 隐藏桌面歌词窗口 → `document.title` 复位为应用名
- `exit()`：移除遮罩，**保持暂停**（不自动续播）
- 遮罩盖住自定义标题栏在内的整个窗口（z-index 最高，不透明而非磨砂）

**主进程**：
- `globalShortcut` 注册老板键，默认 `F9`，设置里可自定义录制（单键/组合键均可），冲突时提示
- 老板键触发 → IPC 推送渲染端切换隐私态；触发动作设置：`仅遮罩` / `遮罩+最小化窗口`
- 隐私期间 `win.setContentProtection(true)`（截图/屏幕共享中窗口呈黑色），退出恢复；设置项可关
- 桌面歌词窗口联动隐藏/恢复
- 快捷键持久化到 settings 表

**UI**：标题栏加隐私按钮（eye-off 图标）；应用内快捷键（默认 `Ctrl+Shift+H`）；设置新增「隐私与老板键」分区（开关、键位录制、触发动作、防截屏、测试按钮）。

## Phase 3：UI 重设计（深色为主双主题）+ renderer 模块化

**设计系统**（重写 styles.css）：
- `[data-theme="dark"]`（默认）+ `[data-theme="light"]` CSS 变量体系：背景/层级/文字/边框/强调色（深色底 + 樱花粉强调，贴合 Sakura 品牌）
- 统一字号/间距/圆角/阴影 scale；消除 21 处硬编码 `#667eea` 和 3 处 JS 内联色
- 组件化：按钮（primary/ghost/danger/icon）、输入框、列表行、卡片、**统一 modal 系统**（合并现有 .dialog-*/.modal-* 两套，原生 confirm 也换成自制确认框）、toast、右键菜单、播放栏、自定义滑块、空状态

**布局重构**（index.html）：
- 标题栏：紧凑 logo+搜索框居中 + 右侧主题切换/隐私按钮/窗口控制
- 侧边栏按新定位分**内容分区：音乐 / 播客 / 听力**（各自计数）+ 歌单区 + 工具区
- 歌曲列表增加缩略图列（Phase 1 CSP 修好后可用）、hover 操作、键盘导航（↑↓选择 Enter 播放）
- 播放栏重设计：封面/信息 + 播放控制 + **倍速按钮 + A-B 复读控件** + 进度条（支持拖拽）+ 歌词/音量

**主题**：接通主进程已有的 `theme-set/theme-get` IPC（main.js:858，目前 preload 未暴露），持久化到 DB。

**renderer.js 拆分**（渐进搬迁，逻辑不变）：`src/player-core.js`（播放引擎）、`src/library.js`（库/列表/歌单/搜索/历史）、`src/dialogs.js`、`src/download-ui.js`、`src/lyrics-ui.js`、`src/context-menu.js`、`src/toast.js`、`src/main.js`（装配）。3060 行巨类解体。
**无障碍补底**：图标按钮 aria-label、焦点样式、列表键盘路径。

## Phase 4：播放逻辑 + 听力特性

- **倍速**：0.5/0.75/1/1.25/1.5/2/3，`playbackRate` + `preservesPitch`（变速不变调），全局持久化
- **A-B 复读**：设 A/B 点区间循环，进度条高亮区间，一键清除（听力核心功能）
- **随机播放重做**：洗牌队列 + 播放历史栈（随机下"上一首"可正确回退）
- **进度条拖拽**：pointer capture 实现，拖动带时间预览
- **睡眠定时**：关/15/30/60/90 分钟/播完停止（播客场景）
- **快捷键**：空格播放暂停、←/→ ±5s（Shift+←/→ ±1s 精听）、↑/↓ 音量
- 播放模式逻辑理顺（死代码已清，按钮语义固定）
- 数据库：`songs` 表迁移加 `content_type`（music/podcast/listening，默认 music），右键可改分类，侧边栏分区过滤

## Phase 5：YouTube 下载

- preload 工具：`isYouTubeUrl`/`extractYouTubeUrl`（watch / youtu.be / shorts / music.youtube.com）
- 下载管线本来就是 yt-dlp 通用流程：IPC 改名 `download-media`（旧名保留兼容），UI 文案改「下载音源」，B站/YouTube 统一入口
- 设置新增「网络」分区：代理地址（传 `--proxy`，国内访问 YT 必需）、cookies.txt 文件选择（年龄限制内容）
- 字幕语言扩展 `zh-Hans,zh,en`（听力场景英文歌词/字幕有价值）
- 倍速信息/缩略图复用现有 yt-dlp JSON 管线

## Phase 6：OCR（图片转歌词）

- 新 `ocr.js` 主进程模块：`ocr-image` IPC，调 **Windows 内置 OCR**（PowerShell + WinRT OcrEngine，zh-Hans+en），零依赖零体积；未装语言包时给出明确引导（设置→语言→添加中文）
- UI：歌词面板/歌曲右键「从图片导入歌词(OCR)」→ 选图 → 识别 → 可编辑确认（textarea 预填结果）→ 存为该歌曲歌词（沿用现有歌词存储管线）
- 识别率兜底：小图可用内置 ffmpeg 预放大（后续按需加）

## 风险与对策

- **系统音量弹窗泄露曲目信息**（Windows SMTC）：Phase 2 测试时专项验证，如泄露则在播放器层处理媒体会话元数据
- 全局单键冲突：注册失败即提示并允许改键；默认 F9 冲突率低
- OCR 依赖系统语言包：优雅降级 + 明确引导，不引入 tesseract（省 40MB+）
- sqlite3 原生模块：只加纯 JS 依赖（extract-zip），避免触发重编译
